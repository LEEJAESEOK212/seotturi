# 데이터 기준 초안

이 문서는 수집·검수용 데이터 기준이다. 학습 라이브러리에 넣는 대화 형식은 이후 별도로 내보낸다.
아래 예시는 설명용이며 실제 확보·검수한 데이터로 집계하지 않는다.

## 보존할 필드

| 필드 | 의미 |
| --- | --- |
| id | 사례의 고유 식별자 |
| source / source_id | 출처와 원본 식별자 |
| region | 확인된 지역. 미상일 때 추정해서 채우지 않는다 |
| speaker_id / conversation_id | 화자·대화 분리용 식별자. 없으면 결측으로 기록한다 |
| parent_id | 합성·변형 사례의 원본 식별자 |
| input_raw | 원본 사투리 문장 |
| input_text | Unicode·불필요한 공백 등 최소 정리 후 입력 |
| context | 실제 확보된 선행 문맥. 추론 시 제공할 수 없는 미래 발화는 기본 입력에서 제외한다 |
| action | convert, keep, clarify 중 하나 |
| standard_text | 검수한 표준어 정답. clarify이면 null |
| accepted_alternatives | 검수한 대체 정답 목록 |
| clarification | clarify일 때 필요한 문맥을 묻는 문장 |
| review_status | unreviewed, accepted, rejected |
| review_note | 의미·말투·애매함 등 검수 근거 |
| provenance | 사람 작성·원본 라벨·교사 생성 여부와 생성 모델 정보 |
| split | train, dev, test |

## 행동 예시

- convert: `퍼뜩 온나.` → `빨리 와.`
- keep: `오늘 좀 늦을 것 같아.` → 입력 유지.
- clarify: 실제 검수에서 문맥 부족으로 판정한 사례를 수집한다. 임의로 모호한 정답을 만들지 않는다.

## 전처리 원칙

1. 원문을 보존한다. 사투리 어휘·어미를 전처리 단계에서 지우지 않는다.
2. 비어 있는 입력·정답, 손상된 데이터, 정답 모순을 집계해 검수 대기열로 분리한다.
3. 입력과 정답이 같다는 이유로 제거하지 않는다. 유지가 적절한지 검수한다.
4. 정확한 중복과 유사 문장·같은 대화·같은 원본의 파생 사례를 조사한다.
5. 그룹 단위로 분할한 다음 학습 데이터만 증강한다. 공식 분할이 있다면 존중하고 누출 여부를 별도로 검사한다.
6. 화자나 대화 ID가 없으면 분리 신뢰도의 한계를 기록한다.
7. 학습 데이터에서만 프롬프트용 예시를 검색한다.
8. 문장 수뿐 아니라 지역·표현 유형·길이·행동별 분포와 제외 사유를 보고한다.

## 초기 구성 가설

학습 데이터의 convert / keep / clarify 비율은 70 / 20 / 10을 초기 검토안으로 둔다.
실제 서비스 입력 분포와 검수 가능한 사례를 보고 수정한다. 비율을 맞추기 위해 저품질 합성 데이터를 채우지 않는다.
최종 평가셋에는 일반 입력 분포와 어려운 유형별 결과를 구분해 기록한다.

## 아직 확인되지 않은 내용

- 원본 데이터 위치, 실제 사례 수와 지역 범위.
- 원본 라벨이 프로젝트의 의미·말투 보존 기준과 일치하는 정도.
- 화자·대화 메타데이터의 존재 여부.
- 모델 토크나이저 기준 길이 분포와 적절한 최대 길이.
- 모델 출력 규약의 구체적인 직렬화 형식과 검증 방식.
